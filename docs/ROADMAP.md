# Roadmap

Not a commitment — a current view of what's planned. Things ship when they're ready.

## Near-term

- **Complete Part I–VI chapters** (v1.0 milestone).
- **Asset coverage parity**: every concept that warrants a drop-in asset has one shipped under `assets/`.
- **Screenshots and asciicast demos** for the first-session chapters (1, 5, 7).
- **Field reports** — short case studies from real users covering a non-trivial task end-to-end. Submit via issue.

## Mid-term

- **Antigravity deep-dive** (Ch. 19) expanded once the product stabilizes and I've run it against three real codebases.
- **Agent eval harness** — a simple, reproducible way to compare two agent configurations on the same repo.
- **Cost observability recipes** — how to actually measure what an agent session costs, in a way your finance team will accept.
- **Onboarding templates** — a `CLAUDE.md` / `GEMINI.md` starter kit by language and stack.

## Long-term

- **Multi-agent coordination patterns** — beyond basic subagent spawning, into ADK-style multi-agent systems for real work.
- **Team rollouts** — rolling agentic coding out across a 50-engineer org without chaos.
- **Security posture** — the full threat model for agentic coding in a regulated environment. Separate doc, not a chapter.

## Explicit non-goals

- **A comprehensive tool comparison matrix.** These go stale in weeks and become a maintenance tax. Chapter 2 is deliberately short.
- **Chasing every new product.** If it's not measurably different from something already covered, it won't get a chapter just for being new.
- **Vendor-specific certifications or partnerships.** This stays independent.

## How to influence the roadmap

Open an issue labeled `roadmap`. If it has upvotes and a clear reader benefit, it moves up.
